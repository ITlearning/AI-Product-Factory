장치Letterboxd 실제 값노래갈피 환산
더 보기서버가 12편 내려보내고 CSS가 3편만 노출

4. 여백 — 카드가 서로 안 떨어져 보입니다

에이전트와 제가 독립적으로 같은 결론에 도달했습니다. 실측

.card { padding: 16px; margin-bottom: 16px } — 안쪽과 바깥쪽이 같은 값입니다.

“internal spacing must always be smaller than external spacing” — Gestalt 근접성 원칙

바깥 = 안쪽이면 뇌가 카드 경계를 여백으로 못 읽고 테두리선에만 의존합니다. 그런데 그 테두리(#2a2624 on #161413)는 대비가 1.23:1로 아주 옅습니다. 묶는 신호가 양쪽 다 약합니다.

margin-bottom: 16px → 24px (--space-5, 이미 있는 토큰). 20곡 총 높이는 1.9%만 늘어납니다.
부수 효과 — 카드 높이의 자연 변주(기억 1편 카드 vs 3편 카드는 높이가 두 배 차이)가 지금은 붙어 있어서 한 덩어리로 뭉개집니다.

5. 제가 코드에서 확인한 결함 3건

#결함확인 방법
1위계 역전. 곡 제목 15px/600 < 본문 17px/400. 색도 같아서 구분이 굵기 하나뿐브라우저 계산값
2시트가 중단되면 점프. 올라오는 도중 닫으면 완전히 열린 위치로 튀었다가 내려감끊은 시점 Y=177 → 클릭 직후 Y=0
35000자 초과를 늦게 알림. maxlength가 없어 계속 쳐지고, 공개 확인 시트를 연 뒤에야 거부5200자 입력 후 재현. 글이 날아가진 않음

2번의 원인: @keyframes sheet-out에 from이 없어 암묵적 시작값이 transform: none(= 열린 상태)입니다. 고치는 법은 @keyframes를 transition으로 바꾸는 것 — transition은 현재 값에서 재조준하고 keyframes는 0에서 다시 시작합니다. Sonner를 만든 Emil Kowalski가 정확히 이 이유로 갈아엎었습니다.

7. 쓰기 화면 — 지금 판단이 맞습니다

Day One은 프롬프트를 입력창 안에 안 둡니다. 우측 패널이나 “More…” 안에 있어서 쓰려고 들어온 사람은 프롬프트를 아예 안 만납니다. 노래갈피가 라벨 칩을 텍스트박스 아래 둔 것과 같은 배치입니다. 문서

절대 넣지 말 것
① 질문형 placeholder / 예시 글 / “영감이 필요하세요?” — 앵커가 둘이 되면 사람은 약한 쪽(질문)을 따라가고 글이 전부 답변체로 수렴합니다. Day One이 프롬프트를 쓰는 건 앵커가 아예 없는 앱이라서이고, 그 대가로 답변체를 감수한 겁니다. 게다가 NN/g의 placeholder 7대 문제 중 회색 대비 미달·기본값 오인·스크린리더 불안정이 다크 테마에 직격입니다.
② 상시 글자수 카운터 / 진행 링 — X의 링이 정당한 건 280자가 제품의 정체성이기 때문입니다. 5000자는 형식이 아니라 방어선이라, 진행 링을 붙이면 채워야 할 목표로 읽힙니다.

폭은 맞습니다 — 영문 66자 규칙을 한글로 옮기면
