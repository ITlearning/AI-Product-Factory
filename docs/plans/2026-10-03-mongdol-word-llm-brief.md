# 몽돌 — 사진을 보는 모델로 단어 고르기 (회의 출발점)

작성 2026-10-03 · 상태 **회의 1차 끝 — 맥스튜디오에서 이어 감** · 진행 기록 `2026-10-03-mongdol-word-llm-session-log.md` · 조사 `2026-10-03-mongdol-word-llm-research.md`

## 왜

Tabber(1.1 실기기 확인 뒤): 「다 문제 없어보여. 그래도 약간 어색한 단어가 나오기는하는데, 이건 이쯤부터는 LLM 이 붙어야할 것 같아. 이건 진짜 사진이 뭔지 인식을 해야하는 단계 같아서」.

1.1 규칙이 보는 것은 Vision 분류 라벨(`structure`·`table`·`food` 수준)과 때·날씨·기온·해 높이까지다. 사진이 **무엇을 담은 순간인지**(생일 케이크 앞의 친구, 빗방울 맺힌 창, 노을 지는 강가)는 끝내 모른다.

## 흔들지 않을 것 (1.1 에서 정한 것)

- 단어는 **사람이 고른 순우리말 목록**(170개, 표준국어대사전 대조)에서만. 모델은 **고르기만** 하고 짓지 않는다.
- 1.1 판정(`WordPicker.judge`)이 **거짓말 막는 문**이다. 모델 답도 이 문을 통과한 후보 안에서만 쓴다(맑은 날 「여우비」 같은 사실 오류는 규칙이 이미 막는다).
- 단어는 사진을 **처음 열 때 한 번** 골라 저장(도장). 실패하면 규칙 1순위. 기다리게 하지 않는다(지금 모델 대기 상한 6초).
- 재촉·판단 금지(SPEC §2).

## 정면으로 부딪히는 약속

- 개인정보 처리방침·사진 권한 문구: 「사진은 기기 밖으로 나가지 않는다」.
- `docs/designs/mongdol-photo-word.md` §2 비목표: **「사진을 AI에 보내는 것」**. 2단계 「AI 한 줄」도 글자만 보내는 설계다.
- App Store 개인정보 표시 「수집 안 함」.

## 회의 안건

1. 사진이 기기 밖으로 나가도 되는가. 된다면 기본 꺼짐 + 켤 때 동의? 어떤 문구로?
2. 모델은 **목록 안에서 고르기만**인가, 목록 밖 단어를 **제안**해 Tabber 가 목록을 키우는 데까지 쓰나.
3. 비용·한도 — 사진 한 장당 얼마, 월 상한, 「처음 열 때 한 번」이면 충분한가.
4. 지연 — 사진을 열 때 몇 초까지 기다릴 수 있나. 하루를 받을 때 미리 골라 둘까.
5. 품질은 무엇으로 재나 — 어떤 사진 세트로, 무엇을 「맞다」로 볼지(Tabber 판정, ↻ 비율).
6. 「AI가 고른 단어」를 표시하나(한 줄엔 뱃지를 붙이기로 했다 — 단어는 사람이 고른 목록이라 붙이지 않았다).
7. 2단계 「AI 한 줄」과 한 번의 호출로 묶나.
