# 디자인/UX 리뷰 — 몽돌 단어: 기기 안 학생 모델과 넓어진 단어 목록

2026-10-04 · 리뷰 대상 [PRD](../../plans/2026-10-04-mongdol-word-model-prd.md) · 관점: 사용자 경험·일관성·빈/오류 상태·디자인 시스템 정합

## 한 줄 판정

**조건부 통과.** 방향(단어가 비지 않음, 이미 붙은 단어 보존, 사진 기기 밖 금지)은 사용자 경험과 잘 맞는다. 다만 「UI 변경 없음」은 사실이 아니다 — 뜻풀이 자리·↻·설정·SPEC 문구가 바뀐다. 사전 원문을 그대로 쓰는 탓에 사용자 화면에 `‘금성03’` 같은 사전 표기가 그대로 찍히는 문제는 출시 전에 고쳐야 한다.

## 잘 된 점

- **빈 상태가 없다.** 모델이 없거나 실패하면 지금 규칙으로 고르고, 「단어가 비는 사진 0」이 성공 기준에 들어 있다. 화면 쪽 빈 상태를 따로 설계하지 않아도 된다.
- **이미 붙은 단어를 건드리지 않는다.** 업데이트 뒤에 예전 사진의 단어가 바뀌면 「내 기록이 바뀌었다」는 배신감이 생기는데, 그걸 막아 두었다. 쉬게 한 단어(`rest`)도 붙은 사진에서는 그대로 남는다.
- **판단하는 말이 없다(SPEC §2-5).** 1,792개 뜻풀이에서 낮잡아·속되게·얕잡아 같은 말을 찾아봤는데 나오지 않았다. 사람이 찍힌 사진에 깎아내리는 말이 붙을 위험은 낮다.
- **글자 폭이 안전하다.** 새 단어는 대부분 2~4자이고 가장 긴 것도 6자(아름드리나무·올망이졸망이)다. 명조 30pt에 ↻(44pt)를 붙여도 375pt 화면 폭(좌우 26 빼면 323pt)에 들어간다. `GlyphRow` 는 `fixedSize` 라 줄이 바뀌지도 않는다.
- 명조 서브셋에 새 글자만 더하고 뺀 단어 글자는 지우지 않는다. 이미 붙은 옛 단어가 대체 글꼴로 깨지지 않는다.

## 위험·빈틈

### 높음

**H1. 사전 표기 찌꺼기가 그대로 화면에 나온다.** 「사전 첫 뜻 그대로」 원칙 때문에 사전 내부 표기까지 따라온다. `words-expanded-v5.json` 확인 결과:
- 동형어 번호·뜻 번호: 개밥바라기 「…보이는 ‘금성03’을 이르는 말」, 별님 「‘별01「1」’을 인격화하여…」, 손님 「‘손02「1」’의 높임말」, 별똥별 「‘유성05’을…」, 샛별, 저녁샛별, 벗님, 갈잎, 사이참, 사잇길, 아가 — 12개 안팎.
- 다른 말을 가리키기만 하는 뜻풀이 13개: 갈바람 「‘가을바람’의 준말」, 아침놀·저녁놀, 얘기꽃, 다림질, 집고양이 「‘집괭이’의 본말」 등. 사진 아래에서 뜻풀이는 낯선 말을 이어 주는 다리인데, 이것들은 그 역할을 못 한다.
- VoiceOver 는 「금성 공삼」으로 읽는다.

제안: 번호·「」 표기는 기계적으로 지운다(뜻은 그대로라 「첫 뜻 그대로」 원칙과 부딪치지 않는다). 준말·본말 13개는 가리키는 말의 첫 뜻으로 바꾸거나 158개처럼 새로 쓴다. 판정 규칙 테스트 옆에 「뜻풀이에 숫자·‘’·「」 없음」 테스트를 하나 둔다.

**H2. ↻ = 「학생 2등」이 「이 단어는 아니에요」라는 말과 어긋날 수 있다.** 학생은 사진 값이 비슷한 말끼리 점수가 붙는다. 그래서 2등이 1등과 거의 같은 말일 가능성이 크다(윤슬 → 물비늘, 노을 → 꽃노을, 아침놀 → 아침노을). 사용자는 「아니에요」라고 했는데 같은 말이 돌아오면 무시당한 느낌을 받는다. ↻ 는 사진마다 한 번뿐이라 되돌릴 수도 없다. 게다가 `hasAlternative` 는 지금 규칙의 `WordPicker.choices` 로 ↻ 를 보일지 정한다. 학생 기준과 달라지면 ↻ 가 보이는데 아무 일도 안 하거나, 반대 상황이 생긴다.

제안: ↻ 의 다음 말은 「2등 가운데 1등과 같은 대상·같은 뜻 갈래가 아닌 첫 말」로 정한다. 공방의 장면 갈래·대상 힌트를 앱에 넣지 않아도, 단어마다 「비슷한 말 묶음 id」 하나만 있으면 된다. `hasAlternative` 도 같은 후보 집합을 보게 하고, 테스트로 둘이 같은 답을 내는지 확인한다.

### 중간

**M1. 뜻풀이가 길어져 화면이 들썩인다.** 13pt 고운돋움은 323pt 폭에서 한 줄에 약 24자 들어간다. 지금 170개는 가장 긴 것이 27자로 거의 한 줄이다. v5 에서는 351개가 두 줄, 10개(48자 넘음)가 세 줄이다. 큰 글씨 설정(`.custom` 은 Dynamic Type 을 따른다)이면 네다섯 줄로 늘어난다. 스크롤 안이라 잘리지는 않는다. 하지만 ↻ 로 한 줄짜리가 세 줄짜리로 바뀌면 `RollingLine` 의 ZStack 높이가 바뀌어 아래 시각·동네·날씨 줄과 지도가 0.9초 뒤 한 번 더 튄다. 제안: 사전 원문도 40자(두 줄)를 넘지 않게 158개 기준을 낮추거나(30개가 44자 넘음), 줄 수가 바뀌는 전환에서 높이 변화를 같은 곡선에 태운다. 이건 화면 변경이니 Wireframe 에 한 줄 적는다.

**M2. 한 자리에 세 가지 말투가 섞인다.** Tabber 가 다듬은 기존 170개(평균 13자), 사전 원문 「…을 비유적으로 이르는 말」「…. 흔히 노인들이 쓴다」(두 문장짜리 150개), 새로 쓴 158개 「봄 길가의 노란 꽃, 씨는 솜털로 날아간다」. 어느 말투가 몽돌다운지는 Tabber 의 판단이니 여기서 고르지 않는다. 다만 끝맺음 형태(명사로 끝남 / 문장으로 끝남, 두 번째 문장 허용 여부)는 하나의 규칙으로 정해 두어야 사진마다 결이 튀지 않는다. 「흔히 노인들이 쓴다」처럼 사진 주인을 두고 하는 말로 읽힐 수 있는 두 번째 문장은 판단 금지(SPEC §2-5)와 아슬아슬하다.

**M3. 모델이 실패한 사진만 「둘러대기」로 돌아간다.** 대비책이 지금 규칙이라, 모델이 메모리 부족 등으로 가끔 실패하면 그 사진에만 「한낮」 같은 시간대 말이 붙는다. 이 PRD 가 없애려던 경험이 조용히 되살아나고, 한번 붙으면 저장되어 바뀌지 않는다. 제안: 실패하면 단어를 바로 저장하지 말고 다음에 열 때 한 번 더 시도한다(지금도 `standingWord == nil` 이면 다시 고르는 흐름이 있다). 모델 파일이 아예 없을 때만 규칙 단어를 저장한다. 디버그 리포트에 「규칙으로 떨어진 횟수」를 남긴다.

**M4. VoiceOver 순서.** 지금은 단어 → 「이 단어는 아니에요, 버튼」 → 뜻풀이 순서로 읽힌다. 낯선 말(볕뉘·갓밝이)일수록 단어 바로 뒤에 뜻이 와야 이해된다. 제안: 단어와 뜻풀이를 한 요소로 묶고(「볕뉘. 작은 틈을 통하여 잠시 비치는 햇볕」) ↻ 는 그 뒤에 둔다. 1,620개를 다 들어 볼 수는 없으니, 받침이 이어지는 말 몇 개(갓밝이·볕뉘·물비늘)만 실기기에서 들어 본다.

### 낮음

- **L1. 출처 문구.** 「단어 뜻풀이 · 국립국어원 표준국어대사전 (CC BY-SA 2.0 KR)」 줄은 버전 줄 아래 tertiary 13pt 라 조용하고 톤도 맞다. 다만 158개를 새로 썼고 기존 170개 중 100개는 사전과 다르다. CC BY-SA 는 고친 사실을 밝히도록 요구하니 「…표준국어대사전을 바탕으로 일부 고쳐 씀」 정도가 정확하다.
- **L2. TinyCLIP MIT 고지 자리가 없다.** 지금 설정에는 라이선스를 보여 줄 곳이 없다(글꼴 OFL 도 표시가 없다). MIT 는 고지 전문이 필요해서 한 줄로는 부족하다. 새 줄이나 화면이 생기니 UI 변경에 넣는다. 「AI」「모델」 같은 말을 그 자리에 쓸지는 아래 결정 2.
- **L3. 사전 원문의 특수 문자.** 뙤새집 「‘口’ 자 모양」의 한자 `口` 는 고운돋움 서브셋(한글·라틴·구두점)에 없을 수 있어 시스템 글꼴로 섞여 찍힌다. H1 테스트에 한자도 넣는다.
- **L4. 업데이트 직후 대비.** 예전 사진은 옛 단어, 새 사진은 풍부한 단어라 하루 상세에서 섞여 보인다. 이건 의도한 보존이라 문제는 아니다. 다만 ↻ 로 옛 사진의 단어를 바꾸면 그때 학생 단어가 들어온다는 점은 SPEC 에 적어 둔다.

## 「UI 변경 없음」 주장 검토

**정확하지 않다.** 단어 자리의 모양은 그대로지만, 사용자가 보는 것이 바뀌는 곳이 다섯 군데 있다.

| 자리 | 바뀌는 것 |
|---|---|
| 뜻풀이 줄 | 거의 한 줄 → 두 줄 351개, 세 줄 10개. ↻ 전환 때 높이가 튄다(M1) |
| ↻ 가 보이는 조건 | 라벨이 없는 사진(약 12%)은 지금 ↻ 가 숨는다. 후보가 수백 개로 늘면 거의 늘 보인다(H2) |
| ↻ 결과 | 다음 규칙 후보 → 학생 2등(H2) |
| 설정 | 사전 출처 줄(별도 브랜치) + MIT 고지 자리(L2) |
| SPEC §3.5a·§9 | 「단어를 길게 눌러」(지금은 ↻), 「LLM 0」, 「Vision 으로 고른다」 문구가 실제와 다르다 |

Wireframe 칸에 HTML 목업까지 그릴 필요는 없다. 위 표와 「뜻풀이 최대 줄 수」만 적어도 충분하다.

## Tabber 결정 필요

1. **뜻풀이 끝맺음 규칙** — 명사로 끝내기(사전식) / 문장 허용(새로 쓴 158개식) / 섞어도 됨. 두 번째 문장(「흔히 노인들이 쓴다」 등 150개)을 남길지도 함께.
2. **설정에서 무엇을 말할지** — 출처만 조용히 적을지, 「단어는 이 기기 안에서 사진을 보고 고릅니다」처럼 기기 안 모델을 밝힐지. 개인정보 약속을 드러내는 장점과, 마법처럼 느껴지던 것이 기계로 보이는 단점이 있다.
3. **↻ 의 다음 말** — 2등 그대로 / 결이 다른 말 중 첫째(H2 제안). 「다른 말 고르기」는 두 번째 PRD 지만, ↻ 의 뜻은 이번 PRD 에서 정해야 한다.
4. **뜻풀이 최대 길이** — 50자(세 줄 허용) / 40자(두 줄까지)로 낮추고 넘는 것은 새로 쓰기.
5. **모델 실패 시** — 규칙 단어를 바로 저장(지금 PRD) / 다음에 열 때 다시 시도(M3).
