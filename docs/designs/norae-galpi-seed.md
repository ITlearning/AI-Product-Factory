# 노래갈피 — 시드 기억

출시 당일 홈을 채울 기억. 운영자 표시를 달지 않는다. Tabber 글도 다른 사람 글과 똑같이 섞인다.

**시드는 규범이 된다. 그래서 일부러 들쭉날쭉하게 쓴다.**

입력창에서 칩과 예시 글을 없앤 이유가 "동질화 압력을 만들지 않기 위해서"인데,
피드는 여전히 예시 역할을 한다. 시드가 전부 비슷한 길이와 형식이면 그 고름이 곧 규범이 되어
사람들이 같은 모양의 글만 쓰게 된다. 이 제품의 가치는 **낯선 사람들의 서로 다른 삶**이다.

- 한 줄짜리, 300자짜리를 **섞는다**
- 시기로 시작하는 것, 곡 얘기로 시작하는 것, 장면부터 던지는 것을 섞는다
- 울먹이는 것도 있고 아무렇지 않은 것도 있게 한다

> 2026-09-16에 쓴 첫 5편은 공교롭게 길이(200~300자)와 형식(회상형)이 비슷하다.
> **짧은 것 몇 개를 일부러 섞어야 한다.**

**계절 구성을 의식할 것.** `지금 계절`은 우선순위 정렬이라 홈이 비지는 않지만,
한 계절에 몰리면 다른 계절에 들어온 사람은 맨 위에 자기 계절 글이 하나도 없다.

- 계절: `봄` `여름` `가을` `겨울`
- 시절: `어릴 때` `학창시절` `대학 때` `군생활` `사회 초년` `요즘`

### 이 표에서 나온 구현 사양

- **`title_key`는 대부분 영문이다.** `골목길 어귀에서`→`attheentrancetothealley`,
  `스며들기 좋은 오늘`→`leanonme`, `고백`→`propose`, `희망고문`→`blues`.
  20곡 중 `그대라는 시` 하나만 us에서도 한글이다. **운영 시 곡을 찾을 땐 `title` 컬럼(한글)을 본다.**
- **아티스트는 필터가 아니라 순위 가중치다.** `프로미스나인` vs `fromis_9`는 kr lookup에서도 안 맞는다.
  제목이 맞으면 후보에 넣고, 아티스트가 맞으면 위로 올린다. 둘 다 요구하면 영문 활동명 그룹이 전부 떨어진다.
- **MR·Inst.가 실제로 섞인다.** 그라데이션 3개, 우연히 잠시라도 2개, 나무 2개.
  괄호·대괄호 **안에서만** `MR`·`Inst`·`남자키`·`여자키`를 찾는다 —
  제목 전체를 검사하면 「노래방에서」가 `노래방` 때문에 오탐된다.
- **`밤산책`은 us에서 `Do Dum Chit`**, `희망고문`은 us에서 `BLUES`.
  us 제목을 화면에 쓰면 사용자가 자기 곡을 못 알아본다.

## 드라이런에서 세어볼 것

시드를 채우면서 기록한다. 이게 리뷰보다 정확한 검증이다.

| 확인할 것 | 결과 |
|---|---|
| iTunes가 못 찾은 곡 / 전체 | **1 / 20 (5%)** — 확정 |
| 유튜브 링크 찾는 데 걸린 단계 (곡당) | |
| 공식 음원이 뭔지 헷갈린 곡 | |
| 글이 어떤 말로 시작하는지 (시기? 곡? 장면?) | |
| 계절 라벨이 안 붙는 기억 | |
| 시절 라벨 6개로 안 덮이는 기억 | |
| 최종 계절 분포 (봄/여름/가을/겨울) | |

첫 5편으로 이미 확인된 것 — **칩은 폐기**(5편 중 0편 적중), **시절 라벨은 6개로 확대**(군생활·대학 때 추가),
**`지금 계절`은 우선순위 정렬로 변경**(5편 중 3편에 계절이 없었다).

남은 편들에서 계속 볼 것은 **계절 분포**와 **시절 라벨 6개가 실제로 덮느냐**다.
여기서 또 안 맞으면 라벨을 한 번 더 손봐야 한다.

## 드라이런 종료 (11편)

**20곡을 고를 때는 다 기억이 있을 것 같았는데, 실제로 쓰니 11편에서 멈췄다.**
곡을 떠올리는 것과 그 곡에 얽힌 장면이 있는 것은 다른 일이다.

이게 제품 가정을 바꾼다 — 한 사람이 계속 쌓는 구조가 아니라,
**한 사람이 한두 편 쓰고 떠나고 사람 수로 자라는** 구조에 가깝다.
카드마다 있는 `나도 적기`는 재방문 유도가 아니라 **새 사람의 첫 글**을 받는 입구다.

시드로는 11편이면 충분하다. 홈에 카드가 두 개씩 보이므로 곡 11개면 넉넉하다.
