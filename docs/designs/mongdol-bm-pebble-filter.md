## Problem Statement

몽돌(사진 일기, 1.0 심사 중·1.1 TestFlight)은 무료이고 결제 수단이 없다. 개발자 등록비(연 $99 ≈ ₩135,000) 정도는 몽돌이 스스로 메꾸게 하고 싶다. 9/28 시장 조사 결론(가끔 쓰는 앱 → 월 구독 안 맞음, 한 번 결제, 쌓인 뒤 가치가 생기는 것을 연다, 증정·기다림에 돈 걸지 않음) 위에서 「무엇을, 어떻게 잠가 팔지」를 정한다.

이 세션은 「사진 100% 클라우드 보관」에서 시작했다가 보류하고 수익으로 옮겨 왔다(아래 결정 기록).

## Demand Evidence

- 사용자는 아직 Tabber 한 명. 유료 의향 근거는 없다 — 이 설계의 수요는 **가설**이고, The Assignment 의 ③이 출시 전 첫 신호를 받는 단계다.
- 조약돌 이름 필터는 Tabber 본인 아이디어(2026-09-28, `docs/plans/mongdol-next-version.md` 「조약돌 이름 필터」): 「찍으면 찍을수록 한 겹 한 겹 쌓이면서 … 조약돌 이름으로 필터를 만들어 준다면 … 맘에 안 들면 사용 안 해도 되고」.
- 바깥 근거(일반): 사진 보관·일기 앱은 사진·기능을 구독 뒤에 둔다(Day One Silver 연 $49.99). 페이월이 기다림을 막으면 무너진다(Dispo, 페이월 뒤 두 달 −78%, 9/28 조사).

## Status Quo

- 사람들은 카메라 앱·편집 앱의 기성 필터를 쓴다. 「내 사진에서 빚어진 내 필터」는 흔하지 않다 — 몽돌만 가진 재료는 그 사람의 조약돌 색과 이름이 쌓인 기록이다.
- 몽돌 안에는 결제가 없다(StoreKit 코드 0). 간직하기(카드·한 달 한 줌·작년 이맘때)는 모두 무료.

## Target User & Narrowest Wedge

- 사람: 순간을 남기고 싶을 때 찍는 사람(포지션 원문: 「순간을 남기고 싶을 때 사용하고, 이 앱으로 남겼다면 소소한 수집도 가능하다」). 이름으로 특정된 사람은 아직 없다 — TestFlight 에서 찾는다.
- 가장 작은 유료: **평생 이용권 하나** — 두 번째 조약돌 이름 필터부터 그 필터로 저장하기.

### 목표 크기 — 실수령액 기준

App Store 가격엔 부가세 10%가 들어 있고, 소규모 사업자 수수료는 15%다. 연 ₩135,000 에 필요한 건수:

| 가격 | 한 건 실수령 | 연 필요 건수 |
|---|---|---|
| ₩4,900 | 약 ₩3,800 | 36 |
| **₩6,900 (제안)** | 약 ₩5,300 | **26** |
| ₩9,900 | 약 ₩7,650 | 18 |

가격은 PRD 에서 확정한다. 아래 기준은 ₩6,900 → 연 26건(넉넉히 30건)으로 잡는다.

## Constraints

- 증정·기다림에 돈을 걸지 않는다(9/28). 매일 쓰게 만드는 장치·알림·재촉 금지(SPEC, DESIGN §1.2 홈에 버튼 추가 금지).
- 공유는 결과가 아니라 도구(메모리 「공유 메커니즘 = 도구 공유」).
- 사진은 기기 밖으로 나가지 않는다. 필터는 기기 안 LUT(`CIColorCube`) — 서버·모델 학습 없음.
- 조약돌 색은 필터 전 원본에서 뽑는다 — 몽돌은 찍는 순간 원본에서 색을 뽑아 기록(`Moment`)에 저장하므로, 필터를 입혀 저장해도 조약돌 색은 원본 그대로다(필터 색 → 조약돌 → 필터 되먹임 방지).
- 사진 앱 저장은 되돌릴 수 있는 편집(`PHContentEditingOutput` + `PHAdjustmentData`). 몽돌은 2026-09-23 부터 이미 읽기·쓰기 권한(`.readWrite`)을 받으므로 새 권한 요청은 없다. 거절한 사람은 지금처럼 몽돌 폴더에 저장하고, 필터 사진도 거기에 필터를 구워 저장한다.

## Premises (합의)

1. 수익 목표는 운영비(연 $99) 정도다.
2. 유료의 주인공은 **조약돌 이름 필터**다.
3. 필터는 쌓여야 빚어지므로, 첫 필터를 잠그면 Dispo 패턴(기다린 내 것을 잠금)이 된다 → 첫 필터는 평생 무료.
4. 모든 필터는 카메라 미리보기로 써 볼 수 있다. 돈은 「두 번째 필터부터 그 필터로 저장」에만.
5. 필터가 실제로 예쁜지, 두 번째 필터가 실제로 생기는지가 모든 것의 전제다.

### B 가 Dispo 패턴과 다른 지점

Dispo 는 **사진 자체**(찍은 순간을 보는 일)를 기다림 뒤 페이월에 묶었다. B 는 사진을 잠그지 않는다.
- 찍은 순간은 언제나 원본으로 저장된다 — 잠긴 필터로 셔터를 눌러도 사진은 바로 남는다.
- 첫 필터(기다려 받은 첫 결과)는 평생 무료다.
- 잠기는 것은 두 번째부터의 「다른 표현」을 저장하는 일뿐이고, 미리보기로는 늘 볼 수 있다.

남는 위험: 두 번째 필터도 「기다려 생긴 내 것」이라 일부는 잠긴 느낌을 받을 수 있다. TestFlight 설문(③)에서 「잠긴 필터를 봤을 때 기분」을 함께 묻는다.

## Cross-Model Perspective

(사진 보관 논의 때 받은 독립 의견 — Codex 로그인 만료로 Claude 서브에이전트.) 요지: 사진 사본 250KB 는 원본 3~5MB 의 1/10 이하라 폰 안에 둬도 되고, 서버 「평생 보관」은 혼자 운영하기엔 책임이 크다. → 사진 보관은 무료 기기 안 사본이면 충분해 수익이 안 붙는다. 이 판단으로 Tabber 가 보관을 보류하고 수익 쪽으로 옮겼다.

## Approaches Considered

### A: 잠금형
빚어진 필터는 모두 잠금, 누르면 결제. 가장 단순(사람 ~1주 / Claude ~1~2일). 기다려 생긴 첫 결과까지 잠가 Dispo 패턴에 가장 가깝다 — 기각.

### B: 써 보고 사기 (채택)
첫 필터 평생 무료, 미리보기 전부 무료, 두 번째부터 저장은 이용권. 사람 ~1~2주 / Claude ~2~3일.

### C: 필터 나누기
B + 이용권 사용자가 내 필터를 친구에게 건넴(도구 공유, 유입). 공유 인프라가 필요해 사람 ~3~4주 / Claude ~1주 — B 위에 나중에 올린다.

결정 기록(한 줄씩): 사진 클라우드 보관 — 보류(폰 안 사본이면 충분, 수익 안 붙음) · AI 문장 2단계 — 뺌(AI 는 온디바이스, 상세 화면 글이 이질적) · 말로 만드는 필터(FilterLab) — 제품은 몽돌과 분리, 색 처리 코드가 쓸모 있으면 몽돌 안으로 복사(공용 모듈 안 만듦) · 기본 필터 몇 개 — 이번 범위 밖(따로 정함) · 올해의 조약돌 — 무료, 이 설계 밖의 따로 기획(12월 일정이 필터·결제와 겹치면 필터·결제가 먼저) · 후원 — 이번엔 안 함.

## Recommended Approach

**B. 써 보고 사기.** 아래 경계 중 「제안」은 Tabber 가 PRD 에서 확정한다.

- **빚어지는 조건**: 같은 이름(`PebbleName`)의 받은 조약돌이 N번 쌓이면 그 이름의 필터가 생긴다. N 은 Assignment ①로 정한다. 더 쌓이면 조금씩 다듬어진다.
- **적용 대상**: 몽돌 카메라로 새로 찍는 사진만. 사진 보관함에서 담은 사진·지난 사진에 입히기는 이번 범위 밖.
- **카메라 칩**: 필터가 하나라도 생기면 카메라 아래 칩 줄이 보인다(알림 없음). 기본 선택은 「원본」이고, 칩을 고르면 미리보기에 바로 입혀진다. 사용자가 처음 아는 길은 카메라를 열었을 때 칩 줄이 생겨 있는 것 하나다. 잠긴 필터 칩에는 **처음부터** 작은 자물쇠가 붙어, 셔터 전에 무료·유료가 구별된다.
- **필터 id·무료 필터**(제안): 필터 id 는 처음 빚어질 때의 조약돌 이름 id 로 고정한다. 처음 빚어진 필터가 무료다. 둘이 같은 날 생기면 받은 조약돌이 더 많은 쪽, 그것도 같으면 N 번째 조약돌을 먼저 받은 쪽. 무료 필터 id 는 정해지는 순간 기록에 저장해 iCloud 로 동기화하고 다시 계산하지 않는다 — 새 기기·이름 체계 변경(후보 「이름을 그날 사진에 맞추기」) 뒤에도 같은 필터가 무료로 남는다.
- **잠긴 필터로 셔터를 누르면**(제안): 사진은 원본으로 바로 저장된다. 그다음 시트 하나 — 「노을빛으로 남기려면 평생 이용권」. 사면 방금 사진에 그 필터를 되돌릴 수 있는 편집으로 입히고, 닫으면 원본 그대로 끝. 시트는 같은 필터에 카메라 화면을 열 때마다 한 번만 — 그 뒤 셔터는 원본 저장만 한다. 결제 도중이든 실패든 찍은 사진은 사라지지 않는다. 사진 권한을 거절해 몽돌 폴더에 저장하는 사람은 구매 뒤 원본을 그대로 두고 필터를 구운 사본을 옆에 하나 더 남긴다(원본은 바꾸지 않는다).
- **이용권**: StoreKit 2 비소모성 상품 하나, 구매 복원, 설정에 「이용권」 한 줄. 홈·알림에는 없다.
- **필터 버전**: 저장할 때 그 순간의 LUT 파라미터를 `PHAdjustmentData` 에 같이 담는다. 필터가 나중에 다듬어져도 예전 사진은 저장 당시 모습 그대로다.
- **기기 변경**: 조약돌 이름·색은 이미 iCloud 로 동기화된다. 필터는 그 기록에서 다시 계산되므로(결정적), 새 기기에서도 같은 필터가 다시 빚어지고 구매 복원으로 이용권이 돌아온다.
- **순서**: Assignment(①②③) → 필터 빚기·미리보기·무료 저장 → 이용권(StoreKit) → (나중) C 필터 나누기.

## Open Questions

- 가격(₩4,900·6,900·9,900)·가족 공유.
- 「다듬어진다」의 규칙 — 새 조약돌마다 바꾸면 같은 필터가 날마다 달라 보일 수 있다. 몇 개마다 다듬을지.
- 1.0·1.1 사용자에게 이용권을 어떻게 알리나(알림·재촉 금지 안에서) — 칩 줄이 처음 생길 때 한 줄 설명이면 충분한가.
- 칩 줄이 카메라 화면을 복잡하게 만드는가(DESIGN 의 여백 원칙).

## Success Criteria

- **출시 전 관문**(Assignment): ① 정한 N 에서 두 번째 필터가 Tabber 기록 그대로면 6주 안, 주 2~3일만 찍는 사람으로 솎아도 12주 안에 생긴다. ② 고른 필터 규칙 하나가 사진 20장에서 「이 필터로 찍고 싶다」 ≥ 70%. ③ TestFlight 15~20명 중 가격을 본 뒤 「살 것 같다」 ≥ 3명.
- **출시 뒤**: 3개월 시점 이용권 ≥ 7건(연 26건의 1/4) — 못 미치면 가격·잠그는 범위를 다시 본다. 1년 26건 이상.
- 결제 시트 때문에 사진을 못 남기는 일 0.
- 필터가 들어간 1.2 TestFlight(4주, 1.1 부터 기록이 쌓인 테스터)에서 첫 필터를 받은 사람의 절반 이상이 받은 뒤 2주 안에 그 필터로 3장 이상 찍는다. 첫 필터를 받은 사람이 5명 미만이면 판정하지 않고 N 을 다시 본다.

## The Assignment

이번 주 안에 맥에서 세 가지를 한다. 셋 다 통과해야 PRD 로 간다.

1. **두 번째 필터가 생기나** — Tabber 의 받은 조약돌 기록(백업 `days.json`)에서 이름별 횟수와 날짜, 한 주에 찍은 날 수를 세고, N = 3·5·7 각각에서 첫 필터·두 번째 필터가 생기는 날을 잰다. 같은 기록을 주 2~3일만 찍는 사람으로 솎아(무작위로 날을 빼서) 다시 잰다. 두 번째가 Tabber 기록으로 6주, 솎은 기록으로 12주 안에 생기는 N 이 없으면 B 는 팔 것이 없다 — 다시 앉는다.
2. **필터가 예쁜가** — 위에서 가장 자주 나온 이름 3개로 필터 규칙 3가지(색 분포 그대로 / 채도·온도만 / 그림자·하이라이트 물들이기)를 만든다(9개). 반복이 N 에 못 미치면 N 을 낮춰 만든다. 사진 20장은 그날 조약돌 이름이 이 3개 안에 드는 날에서만 고르고, 사진마다 그날 이름의 필터를 세 규칙으로 입혀 나란히 놓고 「이 필터로 찍고 싶다」를 판정한다. 한 규칙이라도 ≥ 70%여야 한다.
3. **돈을 낼 사람이 있나** — 1.1 TestFlight 2주 설문에 잠긴 필터 화면 그림과 가격(₩6,900)을 넣고 「살 것 같다 / 모르겠다 / 안 산다」와 「잠긴 걸 봤을 때 기분」을 묻는다. 15~20명 중 「살 것 같다」 ≥ 3명.

## What I noticed about how you think

- 「아 맞네..필터도 생각했었지. 예전에 bm으로 생각했던거도 다 가지고 와서 고려 해야할 것 같아」 — 추천 하나를 고르기 전에 판을 넓혀 다시 봤다. 그 결과 첫 추천(올해의 조약돌)과 다른 답(필터 중심)으로 갔다.
- 「음...그럼 이 부분은 수익화 하기가 어려운 부분이 맞는 것 같아. 지금 당장 문제가 되지도 않아서 이건 일단 보류」 — 자기 아이디어(사진 클라우드)를 숫자 앞에서 바로 내려놓았다.
- 「너무 간략하게 얘기해서 무슨말인지 모르겠어, 세세히 알려줘」 — 이해하지 못한 채로 동의하지 않았다.

### R3-1 — completeness

**Problem**

> 93행은 시트를 닫은 뒤 「그 뒤 셔터는 원본 저장만 한다」고 하지만, 시트를 닫은 뒤 잠긴 칩이 계속 선택된 채 미리보기에 필터가 입혀져 있는지가 없다. 그대로 남으면 사용자는 필터가 입혀진 화면을 보며 찍지만 실제로는 원본만 저장되어, 보이는 것과 남는 것이 다른 채로 여러 장을 찍게 된다.

### R3-2 — feasibility

**Problem**
